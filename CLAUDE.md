# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Vigolium is a high-fidelity web vulnerability scanner written in Go. It operates as a CLI scanner, REST API server with traffic ingestion, or traffic-forwarding ingestor client (`vigolium ingest`). Module: `github.com/vigolium/vigolium`, requires Go 1.27+.

## Build & Test Commands

**IMPORTANT:** Never build the binary directly with `go build` to `./vigolium` or any ad-hoc path. Always use `make build` (outputs to `bin/vigolium`) or `make install` (installs to `$GOPATH/bin`). Direct `go build` bypasses version injection and may leave stale binaries in the working directory.

```bash
make build              # Build main binary → bin/vigolium, installs to $GOPATH/bin
make test               # Run all tests (auto-installs gotestsum)
make test-unit          # Fast unit tests (-short flag, no external deps)
make test-race          # All tests with race detector
make test-e2e           # E2E tests (requires Docker, -tags=e2e)
make test-canary        # Canary tests against DVWA/VAmPI/JuiceShop (Docker, -tags=canary)
make lint               # golangci-lint run
make fmt                # Format code
make tidy               # go mod tidy
```

Run a single test:
```bash
go test -v -run TestFunctionName ./pkg/path/to/package/...
```

Run a single test file with build tags:
```bash
go test -v -tags=e2e -run TestName ./test/e2e/...
```

## Architecture

### Execution Pipeline (Native Scan)

Request ingestion → Scope filtering → Executor (worker pool) → Module dispatch → Result output/storage

This is the **native scan** pipeline — deterministic, Go-based scanning with no AI involvement. The **Executor** (`pkg/core/executor.go`) is the central orchestrator. It receives `HttpRequestResponse` items, distributes them to registered modules via a concurrent worker pool, and collects `ResultEvent` findings. It supports pre/post hooks (`HookRunner`), scope matching, and per-host rate limiting.

### Module System

All scanner logic lives in **modules** registered in the **Registry** (`pkg/modules/registry.go`); the wiring is in `pkg/modules/default_registry_active.go` / `default_registry_passive.go` (currently 207 active + 116 passive registrations = 323 modules). Two types:

- **ActiveModule** (`pkg/modules/active.go`): Sends modified requests to detect vulnerabilities. Methods: `ScanPerInsertionPoint`, `ScanPerRequest`, `ScanPerHost`. Each module declares which `ScanScope` and `InsertionPointType` it handles.
- **PassiveModule** (`pkg/modules/passive.go`): Analyzes existing request/response pairs without sending new traffic. Optional `Flusher` interface for end-of-scan finalization.

Both share the base `Module` interface (ID, Name, Severity, Confidence, Tags, CanProcess, ScanScopes). Modules are tagged with classification labels (e.g., `spring`, `xss`, `light`) and can be filtered with `--module-tag` CLI flag or `?tag=` API parameter.

Module helper code lives in `pkg/modules/modkit/` (shared constants, default implementations) and `pkg/modules/infra/` (block detection, request filtering, response transfer).

### Ignored Directories

- **`platform/`** — Contains external tooling only. Do not read or modify files in this directory, except for `platform/vigolium-workbench/` which is the Next.js UI frontend — only go into it when making changes to the UI.

### Key Packages

- **`pkg/core/`** — Executor, worker pool, rate limiter, network utilities, scan statistics
- **`pkg/modules/`** — Module interfaces, registry, all active/passive scanner modules
- **`pkg/deparos/`** — Spider & discovery engine: crawling (`discovery/`), JS analysis (`jstangle/`), fingerprinting (`fingerprint/`), Wayback integration (`wayback/`), scope enforcement (`scope/`), WAF detection (`waf/`), storage (`storage/`)
- **`pkg/harvester/`** — The `external-harvest` phase: URL collection from public archives and indexes, wired in `internal/runner/runner_targets.go` (`buildExternalHarvesterSource`) and configured under `external_harvester` in `internal/config/external_harvester.go`. Keyless sources (`wayback`, `commoncrawl`, `alienvault`, `arquivo`) are the default set; `urlscan`/`virustotal` join only when their key is configured. Four contracts govern it. **Index rows are passed through verbatim, mined URLs are filtered** — an index row is what the archive recorded and is emitted unchanged (including the malformed URLs a scanner once requested and the archive dutifully stored), while a mined URL comes from a page body and is scope-checked on a label boundary, junk-extension filtered, and stripped of archive hostnames; without that, mining a page would fan the scan out across every CDN, analytics host and font provider it references. Provenance rides on `Result.Mined`, not on a synthetic source name, so `Result.Source` always equals some `Source.Name()`. **`wayback` and `commoncrawl` mine bodies, not just indexes**: wayback replays captures through `/web/<ts>id_/` (the `id_` is load-bearing — without it the archive rewrites every link in the body to point back at itself, so mining would return a list of web.archive.org URLs) and walks each main host's robots.txt history with `collapse=digest` (one row per *content* change, so a decade of daily captures collapses to the handful of times the file was edited — the old `Disallow:` lines are the point, since they name paths no crawler was ever allowed to record); commoncrawl range-fetches the WARC record each index row already locates via `filename`/`offset`/`length`, which is one gzip member of a few KB rather than the multi-gigabyte file, and a response that is not `206` is refused rather than parsed. **Mining is gated on the index carrying timestamps** (`hasTimestamp`) — a replay is addressed by timestamp, so a response without them means the field list was not honored and firing anyway would spend a request per host to learn that. **The relative-URL extractor validates the *cleaned* candidate, never the raw match**: `(` is deliberately not accepted as an opening delimiter (in JS, `(` before `/` is a regex literal far more often than a URL — Angular alone contributes `/&/gi`, `/=/gi`, `/@/gi`, …), a path must start with a name character and be at least two characters after the slash, and the regex-literal shape `/x/gi` is rejected; validating before `cleanCandidate` trims trailing punctuation lets `'/g,` survive as a two-character "path". Every budget is a constant in `mine.go`, not a flag, because the phase runs unattended.
- **`pkg/agent/`** — Agentic scan engine: prompt templates, context enrichment (`autopilot_context.go`), the autopilot pipeline runner (`autopilot_pipeline.go`) and swarm runner (`swarm.go`), output parsing (findings/HTTP records/attack plans/triage results/source analysis), and database ingestion. All AI dispatch goes through the in-process olium engine via `olium_adapter.go` — there are no subprocess SDK backends. Powers the agentic scan modes (autopilot, swarm) and the query mode.
- **`pkg/olium/`** — In-process Go agent runtime: provider drivers (`provider/` for openai-codex-oauth, anthropic-api-key, anthropic-oauth, openai-api-key, anthropic-cli), turn-based engine (`engine/`), tool registry and built-ins (`tool/`), skills support (`skill/`), the autopilot agentic loop (`autopilot/`), TUI (`tui/`), and headless one-shot helper (`headless.go`). Used by every agent mode and exposed directly via `vigolium agent olium` (alias `vigolium olium` / `ol`).
- **`pkg/audit/`** — Vigolium Audit harness driver: parser for the audit's on-disk output (`pkg/audit/parser.go`, `constants.go`), embedded binary management (`pkg/audit/bin/`), per-platform cost/stream support (`claudecost/`, `codexcost/`, `stream/`). Drives the `vigolium agent audit` foreground mode.
- **`pkg/jsext/`** — JavaScript extension engine (Grafana Sobek). Exposes `vigolium.http`, `vigolium.scan`, `vigolium.ingest`, `vigolium.source` APIs. TypeScript definitions in `vigolium.d.ts`
- **`pkg/httpmsg/`** — HTTP request/response model, insertion points, serialization
- **`pkg/http/`** — HTTP requester with middleware pipeline
- **`pkg/input/`** — Input source adapters (OpenAPI, Swagger, WSDL/SOAP, Postman, Burp, cURL, Nuclei, HAR). `formatRegistry` in `pkg/input/source/file.go` is the single source of truth for which `-I/--input-mode` values exist; `resolveFormat`, `SupportedFormats`, and the `--list-input-mode` table all derive from it. **`-i/--input` vs `-T/--target-file` is not a free choice**: `-T` reads its file as one target URL per line, so a spec or an export must go through `-i` — pointing `-T` at a YAML spec makes every line of that file a target (and under `-S` fans out one child scan per line). The two exceptions are the formats that *are* target lists: `urls` and `burpscope`. `formats/burpscope/` parses a Burp Suite project-config scope export (`{"target":{"scope":{"include":[…],"exclude":[…]}}}` — the file a bug-bounty program hands out, **not** the proprietary binary `.burp` project file) and expands its include rules into seed URLs. It is content-sniffed (`burpscope.SniffFile`) on both the `-T` path (`readTargetFileLines`) and the FileSource path, where it displaces only the `urls` default so an explicit `-I` always wins. Three rules govern the expansion and must not regress: a **wildcard host is never guessed at** (`^.*\.example\.com$` names a set, not a server — synthesizing the apex would send traffic at a host the scope never listed, so it is reported via `Result.WildcardHosts` instead), an `http://` candidate is **collapsed into its `https://` twin** when the same host+path is in scope over both (Burp writes both for every host; the http one is a redirect in practice) but an explicit non-default port survives as a distinct service, and **exclude rules are applied to derived targets** before they are emitted. A scope that yields zero targets is a hard error, not an empty run. The curl parser (`formats/curl/`) is **table-driven and strict**: every recognized flag declares whether it consumes an argument, and an unknown flag is a hard error rather than a skip. Skipping only the flag leaves its value looking like a bare token, i.e. the URL — so `curl -e https://referer/ https://target/` used to silently retarget the request at the referer's host. `ParseSingleCommandWithHints` additionally returns `TransportHints` (proxy, timeouts, TLS material, HTTP version, `--resolve`) that don't fit in the request bytes. The WSDL parser (`formats/wsdl/`, `-I wsdl`, aliases `soap`/`svc`) turns a WSDL 1.1 / SOAP service description into one POST request per bound operation the same way `openapi` turns a spec into requests — each carries a synthesized SOAP envelope (SOAP 1.1 with a `SOAPAction` header + `text/xml`, or SOAP 1.2 with `action=` in `application/soap+xml`; document/literal or rpc) whose XML body the active-module fleet fuzzes via the existing `INS_PARAM_XML`/`INS_PARAM_XML_ATTR` insertion points. The XSD→body generator (`xsd.go`) is best-effort: it resolves refs/types **by local name** (prefix-agnostic, robust to `xsd:`/`s:`/`tns:`), depth-caps recursion (`maxGenDepth`), and degrades deep/unknown types to a placeholder skeleton rather than failing an operation; multi-file `<import>` and WSDL 2.0 are not resolved (for a `.svc`/`.asmx` URL the loader fetches `?singleWsdl`/`?WSDL`, which inlines schemas). The endpoint is the WSDL's `<soap:address>`, host-overridden by `-t` (scheme+host from `-t`, path from the WSDL — mirrors OpenAPI `BaseURL`). Two traps: the `SOAPAction` header is written via a **direct `req.Header[...]` map assignment**, never `Set` (which canonicalizes it to `Soapaction`, rejected by some picky stacks — `DumpRequestOut` writes map keys verbatim); and the `-t`+`-i` combo builds a **`MultiSource`**, so all three option-injection sites (`scan.go`/`ingest.go`/`runner.go`) resolve the file parser through `source.FirstFileSource` (which unwraps a `MultiSource`) rather than a bare `*FileSource` assertion — a bare assertion silently dropped the override for OpenAPI too. `wsdl.SniffFile`/`IsWSDL` content-sniff a WSDL (definitions + WSDL + SOAP namespaces) so `-i service.wsdl` needs no explicit `-I`, and `specutil.DetectSpecType` returns `WSDL` so a `?wsdl` response found mid-crawl is auto-expanded into scan traffic (the same discovery/spider/passive/active auto-ingest path OpenAPI/Postman ride; `IsSpecContentType` widened to XML, gated by the strict WSDL marker check).
- **`pkg/server/`** — REST API server (Fiber), Swagger UI, ingestion handlers, agent run API (`handlers_agent.go`)
- **`pkg/database/`** — Repository pattern over SQLite (default) or PostgreSQL via Bun ORM. Supports `SaveRecordBatch` for bulk HTTP record ingestion and `DeduplicateRecordsBySource` for per-source deduplication
- **`pkg/queue/`** — Hybrid queue (in-memory + disk/Redis spillover)
- **`pkg/output/`** — Result formatting, output handlers, and HTML report generation (`format_html.go`)
- **`internal/config/`** — Configuration management, scope matcher, agent config (`agent.go`)
- **`internal/runner/`** — High-level scan runner orchestration
- **`internal/logger/`** — Zap-based structured logging

### Multi-Tenancy (Projects)

All scan data is scoped to a **project** via `project_uuid` on all data tables (scans, http_records, findings, scopes, oast_interactions). The CLI `project` subcommand manages projects (`create`, `list`, `use`, `config`). The `--project-uuid`/`--project-name` flags and `VIGOLIUM_PROJECT_UUID`/`VIGOLIUM_PROJECT_NAME` env vars scope CLI operations; the `X-Project-UUID` header scopes server API operations. Config merges: global → project → scanning profile → CLI flags. See `docs/projects.md`.

**Which database a command opens** is `--db` → `$VIGOLIUM_DB_PATH` → `database.sqlite.path` from the config file → the built-in default. The env var (`pkg/cli/db_path_env.go`, applied once in root's `PersistentPreRunE` — the only seam upstream of both `clicommon.GetDB` and the ~7 sites that assign `settings.Database.SQLite.Path = globalDB` directly) exists so a shell can be pinned to one session database. It carries one asymmetry that must not be flattened: reads treat the pinned file as a **stateless source** (project scoping off), writes do not. That implication lives in `statelessReadRequested` (`stateless_db.go`) — the single predicate `openReadDB`/`openExportDB`/`effectiveProjectUUID` already consult — and **not** in a list of command names, so a reader is covered the moment it asks the question (`fuzz -u <uuid>` resolves records through `effectiveProjectUUID` while registering no `-S` flag at all, and would be silently project-scoped under a name list). The env var never writes `globalStateless`: on `scan`/`scan-url`/`scan-request`/`run` that flag means "scan into a throwaway temp DB" and is a hard error alongside `--db`, so setting it would break every scan with a `--db` the user never typed. The converse guard — an explicit `-S` making the env var a no-op — keys off `cmd.Flags().Lookup("stateless").Changed` rather than `globalStateless`, because the flag name has three separate bindings (`globalStateless`, `auditStateless` on `vigolium audit`/`agent audit`, and `--scan-on-receive` on `ingest`/`server`). Auto-stateless is gated on the file existing (`statelessSourceUsable`, shared with the opener it predicts), since a stateless read stats its source and would otherwise fail on the first read of a not-yet-written session. Validation that names flags in its error message (e.g. `traffic --save-to-vigolium-db`) must check the explicit flags, not `statelessReadRequested`, or it reports flags the user never passed.

### Reading a large `--glob-db` set

`--glob-db` merges a glob of result files and is routinely pointed at hundreds of them (a per-host bug-bounty run: ~854 files, 16 GB, 290k `http_records`, ~55 KB of raw request/response per record). At that size the merge, not the query, is the whole cost — it runs **before the first `WHERE`**, so anything copied in is resident before any filter narrows it. Four contracts keep it bounded, and each was a measured collapse into swap before it existed.

**The scratch database is a temp FILE, never `:memory:`** (`newTempDB` / `newScratchDB`, `pkg/cli/scratch_db.go`, used by `openGlobDB`, `loadStatelessJSONL` and `openGlobSourceFile`). In memory the merge is anonymous heap that cannot be evicted, so it competes with the process's own allocations and thrashes — 18.7 GB RSS and 149s of *kernel* time for an `export` that never finished. On a file the same working set is paged against the OS page cache, and a glob small enough to fit stays in cache anyway, so nothing is lost at the small end. `synchronous=OFF` and `journal_mode=MEMORY` differ from the normal defaults — the file is disposable, and fsync plus WAL's double-write (once to the `-wal`, once at checkpoint, drained in ~4000 passes at the default 1000-page autocheckpoint) are what dominate a bulk load this size. **`journal_mode` must not be OFF** — `mergeOnce` wraps each file's copy in a transaction with a deferred `Rollback`, and rollback without a journal is undefined; MEMORY keeps that while costing only concurrent reader/writer access, which nothing here needs. **`MaxOpenConns` must stay at the default** — `:memory:` is pinned to one connection because each connection there gets its *own* database, which is a constraint of in-memory SQLite rather than something callers were written against; `export` streams rows while issuing further queries and deadlocks outright against a single connection. `closeDatabaseOnExit` removes the directory; `reapStaleScratchDBs` collects what a killed run stranded (age-based, not pid-based — a pid check that is wrong on some platform deletes a live merge's database, where an over-long window only delays cleanup).

**On `finding`, an output mode may never pull records into the merge; only a filter may** (`findingGlobSkipSet`). The merge records the skip set it ran with (`globDBSkipped`, beside `globDBSources`/`globRecordFile`) and the read site asks `globMergeOmittedRecords()` — the decision has one owner, because a second derivation from the flags is one that can disagree, and the symptom of disagreeing is silently empty evidence rather than an error. A filter runs in SQL and cannot be applied after the fact — an output mode can. So `--raw/--burp/--markdown/--with-records/--push-to-burp/--to-repeater` no longer force `http_records` in (that copied every file's whole corpus to hydrate the ~100 findings on screen: 20.4 GB); they hydrate afterwards by uuid via `loadGlobFindingRecords`, walking each finding's own source file (`globSourceForFinding` already attributes merged finding ids to files), with a sweep for anything the attribution misses. The skip is three-tier, gated on `QueryFilters.UsesLinkedRecords()` (findings have no record columns of their own — host/path/method/status/source all resolve through an `EXISTS` over `finding_records`) and `UsesRawCorpus()`. Both failures are silent: with the table absent every `EXISTS` is false, so `--host` returns nothing and the negated `--exclude-*` forms return everything.

**`traffic --save-to-burp` under `--glob-db` never merges at all** (`saveGlobToBurp`, `pkg/cli/traffic_burp_glob.go`). It is the one mode that cannot drop the bodies — they are what gets sent — so it streams file-by-file instead, bounding peak memory by the largest single file (16 GB → 417 MB). It does not fall through to the listing afterwards: that would re-query the corpus a third time and, with `-B` set, also pull Burp's entire proxy history to merge in. Dedup by uuid, the `-n` budget, and `--offset` are carried by `globBurpSelector` because they no longer come from one merged table; the budget is spent in file order, which is immaterial for a Site map copy.

**A single-format `export` streams rather than materializing** (`exportJSONL` → `streamJSONLExport`). `exportRun.loadItems` memoizes the envelope set so a *multi*-format run reads the database once; for one format that memo is pure cost (290k envelopes, ~6.1 GB). `streamJSONLExport` (`pkg/cli/scan.go`) already existed for exactly this and produces byte-identical output, so the only addition is that it returns the `exportCounts` tally — accumulated on the way past, or over a finished slice via `countExportItems` — which is now the one currency the summary block prints.

### Agent Mode

The `vigolium agent` command runs AI agents for security analysis. The parent command only supports `--list-templates` and `--list-agents` flags — all execution requires a subcommand. All AI dispatch is routed through the in-process olium engine (`pkg/olium/`); there are no subprocess SDK backends.

- **Query** (`vigolium agent query`): Single-shot prompt execution with template-based or inline prompts. Supports `--source` for code path, `--source-label` for ingestion label. Returns structured output (findings or HTTP records). Good for code review, endpoint discovery, secret detection. Not an agentic scan — no network scanning or multi-phase orchestration.
- **Autopilot** (`vigolium agent autopilot`): Agentic scan mode — autonomous scanning. The CLI delegates to `pkg/olium/autopilot.Run`; the server's HTTP handler runs the same loop wrapped by `agent.AutopilotPipelineRunner` so it can layer vigolium-audit prep, auth preparation, and a frozen context bundle in front of the operator agent. Accepts `--input` (curl, raw HTTP, Burp XML, base64, URL) with auto-detection and stdin piping. When `--source` is provided, the agent operates with filesystem read/write access to the source tree. `-S/--stateless` runs the whole autopilot into a throwaway temp DB (project DB untouched, mirrors `vigolium scan -S`) and materializes `--format` outputs from it afterward; `--format` is the same comma-list the scan commands accept (`console,jsonl,html,report,pdf,sqlite,fs`), with `-o/--output` as the shared base (default `vigolium-result/vigolium-autopilot`). The shared machinery lives in `pkg/cli/agent_stateless_export.go` (`planAgentStateless`/`beginAgentStateless`/`emitAgentStatelessExport`) and reuses the scan side's `finishStatelessExport`. Five invariants: (1) a file-producing `--format` is a **hard error without `-S`** (a persisted agentic run has no live output writer — export the project DB afterward instead), not the silent no-op a root-persistent `--format` used to be; (2) `-S` is rejected alongside `--db`, `--db-isolate`, and `--resume`; (3) `beginAgentStateless` **sets** `$VIGOLIUM_DB_PATH` to the scratch path so the operator's `bash`-tool `vigolium` subprocesses write into the same throwaway DB — which is why `autopilot` is in `statelessWriteCommands` (else a re-read of the env var would flip reads to project-scoping-off mid-run); (4) the native scan paths the operator launches read `settings.Database`, so `applyAgentStatelessSettings` repoints that too, not just `globalDB`; (5) the export is emitted from the invocation that actually ran the operator (the NL-prompt path re-enters `runAgentAutopilot(nil,nil)` — the only nil-`cmd` caller, which is why the plan is resolved under `if cmd != nil` so the DB is minted once; `emitAutopilotStatelessExport` clears `plan.output` after writing so it exports once — a multi-app NL prompt runs every app into one scratch DB and exports the combined result once via `runMultiAppAutopilot`'s deferred emit). The `--format` list, its `sqlite3`/`db` aliases, and its error message come from `normalizeScanFormats`/`scanOutputFormats` in `pkg/cli/scan.go`, shared with `reconcileOutputFormats`, so `scan -S` and `autopilot -S` accept exactly the same set. `swarm` does not yet carry `-S`.
- **Swarm** (`vigolium agent swarm`): Agentic scan mode — AI-guided vulnerability scanning, supporting both targeted single-request and full-scope scanning (with `--discover`). The master agent analyzes inputs, selects scanner modules, generates custom JS extensions, executes scans, and optionally triages results (with `--triage`). Phases: normalize → source analysis (AI, conditional) → code audit (AI, conditional) → discover (native, conditional) → plan (AI) → extension → native scan → triage (AI, conditional) → rescan (loop). Supports `--source` for AI-driven source code analysis and `--code-audit` for deep AI security code audit. When inputs exceed 5 records, master agent calls are batched (max 5 per batch) with plan merging. `--target` is required when `--source` is used.
- **Olium** (`vigolium agent olium` or top-level `vigolium olium` / `ol`): Direct interactive (TUI) access to the olium agent. Pass `-p "..."` (or `--prompt`) to run a single prompt non-interactively and stream to stdout — useful for ad-hoc prompts and debugging providers.
- **Audit** (`vigolium agent audit`): Foreground vigolium-audit driver (separate harness — does not use olium). Drives the embedded vigolium-audit harness against a source tree using the `claude` or `codex` CLI. Agent selection: `--provider <olium-provider>` resolves the agent **and** forwards that provider's BYOK auth (`anthropic-*` → claude, `openai-*` → codex; empty inherits `agent.olium.provider`); `--agent {claude|codex}` is a pure agent selector layered on top — it overrides the provider-implied agent while keeping the resolved auth (`agent.ForceAuditAgent`, invalid values rejected up front). Same flags exist on `vigolium agent audit` (audit leg only).
- **Piolium** (Pi-native audit driver): Drives the user's installed piolium Pi extension via `pi --mode json -p /piolium-<mode>`. Same finding schema as audit, tagged separately in the DB. There is no standalone `vigolium agent piolium` subcommand — piolium runs only through `vigolium agent audit` (`--driver=piolium` for piolium alone). The shared driver helpers live in `pkg/cli/agent_piolium.go`.
- **Audit** (`vigolium agent audit`): Unified driver dispatcher — runs audit and/or piolium against the same source tree under one parent AgenticScan, with per-driver child rows. Default `--driver=auto` **preflights** the audit leg and falls back to piolium only when audit cannot start - the resolved `claude`/`codex` CLI is not on PATH, the audit binary is not embedded, or the mode chain has no audit-supported mode. When the preflight passes, audit runs and piolium is never consulted **whatever the audit's outcome**: a mid-run audit failure surfaces rather than silently retrying on piolium (so a missing piolium runtime is not reported up front). The identical preflight governs the CLI (`orchestrateAuditDrivers`) and the server (`runDriversSequentially`). `--driver=both` runs audit then piolium unconditionally and sequentially. Both run a post-pass project-wide findings dedup; `--driver=piolium|audit` forces a single driver. Audit-leg agent selection uses `--provider`/`--agent {claude|codex}` (see the Audit entry above; `--agent` warns rather than errors under `--driver=piolium`). `--modes a,b,c` (or REST `modes: [...]`) chains modes back-to-back, stopping on the first non-complete mode: audit runs the chain natively via its own `--modes` (one subprocess, one row, aggregate cost — `auditstream` sums the per-mode `result` events); piolium chains via sequential `pi` runs in the same source tree collapsed into one aggregated child row (`pkg/agent/audit_chain.go` `PioliumChainScanner`). For `--driver=auto|both`, modes a driver can't run are skipped on that driver's leg (per-driver `ValidateAuditDriverModes`); a mode unknown to both drivers is a hard error. `--intensity deep` resolves to the chain `deep,confirm` (quick→`lite`, balanced→`balanced` stay single-mode) across `vigolium agent audit`, `vigolium agent audit`, and the `POST /api/agent/run/{audit,audit}` endpoints. `vigolium agent audit --list-modes` / `vigolium agent audit --list-modes` print the embedded audit binary's `list` (mode graph: phases, time estimate, descriptions) and exit. `vigolium audit` is a top-level alias for `vigolium agent audit` (same flags, via `registerAuditFlags`). `--keep-raw` is **on by default** for the CLI (the REST `keep_raw` default is unchanged): it forwards audit's `--keep-raw` AND retains the `<source>/vigolium-results/` source-tree copy (`KeepSourceOutputDir`); `--clean-raw` removes that source copy after the run (the session copy is always kept; `--keep-raw`+`--clean-raw` is a hard error). `-S`/`--stateless` runs the whole audit into a throwaway temp DB (main DB untouched, mirrors `vigolium scan -S`) and, after completion, auto-renders a self-contained HTML report from the run's findings via the `vigolium import --format html` generator to `vigolium-result/vigolium-audit-report.html` (override with `-o`/`--output`, which supports `gs://` and `{ts}`); `-S` is rejected with `--interactive`. `--output-dir <dir>` (stateless-only) bundles the HTML report (as `<dir>/vigolium-audit-report.html`) **and** a copy of each ran driver's raw `vigolium-results/` tree into one folder — one driver lands flat at `<dir>/vigolium-results/`, multiple are namespaced under `<dir>/<driver>/vigolium-results/`; the source-tree copy is left in place (per `--keep-raw`); a relative `-o` nests under `<dir>` while an absolute path or `gs://` URL escapes it, and `{ts}`/`{project-uuid}` in `<dir>` are expanded once so report + raw copy share the same directory. `-S` without `--output-dir` warns that raw output stays under `<source>/vigolium-results/`; `--output-dir` without `-S` warns and is ignored (mirrors `-o`). Audit-leg report/bundle helpers: `pkg/cli/agent_audit_report.go` `emitAuditStatelessReport` / `resolveAuditReportDest` / `bundleAuditRawResults`.

Source code context is provided via the `--source` flag across all agent subcommands. The `Options.SourcePath` field carries this through the agent engine. The `TemplateData.SourcePath` variable is available in prompt templates. The legacy `--repo` flag has been removed entirely.

All agent modes create a session directory under `sessions_dir` (configurable via `agent.sessions_dir` in `vigolium-configs.yaml`, defaults to `~/.vigolium/agent-sessions/`). Session dirs store agent artifacts: `runtime.log`, `transcript.jsonl` (Pi-compatible olium conversation transcript), `extensions/`, `session-config.json`, `swarm-plan.json` (swarm), `master-output.md` / `source-analysis-output.md` / `code-audit-output.md` (per-phase outputs), `audit-stream.jsonl` (audit), `checkpoint.json` (swarm resume). The `EnsureSessionDir(baseDir, runID)` helper in `pkg/agent/pipeline_types.go` creates the directory structure.

The `transcript.jsonl` is a machine-readable, append-only conversation log of an olium engine run, written by `pkg/olium/sessionlog` and shaped to match the Pi coding agent's session-log schema (a parentId-chained event tree: `session` header → `model_change` → `thinking_level_change` → `message` lines for roles user / assistant / toolResult, with full tool arguments and untruncated tool results). It is produced via a single tee at `engine.Engine.Run` (`engine.Config.Recorder`, the `engine.EventRecorder` interface), so the olium TUI (`olium`/`ol`), headless (`-p`), and autopilot all emit one without touching their drain loops; closed via `Engine.CloseRecorder()`. Forks do not inherit the recorder (concurrent sub-runs would interleave one file). Distinct from `runtime.log` (human-readable tool-card log) and `audit-stream.jsonl` (the separate vigolium-audit harness, not olium). Swarm/query phases also emit transcripts now: the `pkg/agent` runtime attaches a recorder in `buildOliumEngineWithSpec` driven by `SessionSpec.Record` (an `agent.RecordSpec`), writing **per-phase** files `transcript-<template>.jsonl` under the session dir (concurrent same-template calls — swarm plan batches — get `-2`/`-3` suffixes via `uniqueTranscriptName` so they never corrupt one file). The fresh-per-call path (`RunPrompt`) flushes via `defer eng.CloseRecorder()`; the reused-session path (source-analysis explore) flushes via `AgentSession.Close()` (forks carry no recorder). Live model reasoning is rendered to a muted `⋈ thinking` stderr lane under `-v/--verbose` in autopilot and swarm/query, centralized in `pkg/olium/toollog` (`HandleThinking`/`FlushThinking`, sharing `CompactThinking` with the TUI). Fidelity caveat: structurally Pi-compatible and readable, but provider-opaque resume fields (message signatures, the per-component cost split, `responseId`) are omitted — the log is for debugging, not for replaying back into Pi.

Prompt templates are Markdown files with YAML frontmatter stored in `~/.vigolium/prompts/` or embedded in the binary (`public/presets/prompts/`). Output schemas: `findings`, `http_records`, `attack_plan`, `triage_result`, `source_analysis`. The olium engine is configured under `agent.olium` in `vigolium-configs.yaml` — see `OliumConfig` in `internal/config/agent.go`. Key fields: `provider`, `model`, `oauth_cred_path`, `oauth_token`, `llm_api_key`, `reasoning_effort`, `max_turns` (default 32), `max_concurrent` (default 4), `call_timeout_sec` (default 600), `cache_size` (default 1024). Providers: `openai-compatible` (default, default model `gemma4:latest`), `openai-codex-oauth`, `anthropic-api-key`, `anthropic-oauth`, `openai-api-key`, `openai-responses` (public OpenAI Responses API `/v1/responses`, API-key auth), `anthropic-cli`, `anthropic-compatible` (Anthropic Messages `/v1/messages` at a custom `custom_provider.base_url`). The Responses wire format (request `input`/`tools` + `response.*` SSE state machine) is shared by `openai-codex-oauth` and `openai-responses` via `pkg/olium/provider/responses_stream.go`. REST API endpoints: `POST /api/agent/run/{query,autopilot,swarm,audit,audit}`, `GET /api/agent/status/list`, `GET /api/agent/status/:id`, `GET /api/agent/sessions[/:id[/logs|/artifacts[/:filename]]]`, `POST /api/agent/chat/completions` (OpenAI-compatible). The audit endpoint takes `driver: "auto"|"both"|"audit"|"piolium"` (default `"auto"`); `auto` preflights the audit leg and falls back to piolium only when audit cannot start (never on a mid-run audit failure), `both` runs both unconditionally, and both multi-driver modes dispatch sequentially, multiplexing SSE chunks with a `driver` field when `stream: true`. The agent request types use `EffectiveSourcePath()` methods for backward-compatible `source`/`repo_path` JSON field handling. See `docs/agentic-scan/agent-mode.md` for the full guide.

### Spidering (`pkg/spitolas`)

Browser-driven crawling. The engine is a state machine, not a link-follower: states are stripped-DOM snapshots (`internal/state`, with near-duplicate clustering and VIPS/landmark fragmentation), edges are `action.Eventable` transitions, backtracking walks a shortest path, and action selection defaults to the adaptive MAB strategy. The runner phase is `runSpideringPhase` (`internal/runner/runner_phase_discovery.go`); `PhaseTargetedReSpider` re-crawls rich/SPA routes discovery found afterwards.

Invariants that must not regress:

- **The DOM snapshot decides state identity, so it must be taken settled.** `settleBeforeCapture` (`internal/crawler/precapture.go`) runs *before* `captureState` in both `inspectNewState` and `checkOnURLState`. This is distinct from `settleNewState`, which runs *after* a state is accepted (and takes an `alreadySettled` flag so a navigating action does not pay two multi-second waits over one page). Getting the order wrong is a silent false-negative path, not a cosmetic issue: a client route change that is still showing the previous route's skeleton compares as a duplicate of the state it came from and is discarded outright, so the later settle is never reached.
- **The settle gate is load-bearing for runtime, not just tidiness.** A settle has a floor of one poll window and a ceiling of ~14s, and `settleBeforeCapture` runs on every executed action, so it fires only when the URL moved or `pageStateScript` reports a visible spinner/skeleton/`aria-busy`. **`previousURL == ""` means "skip the URL compare and decide on the busy probe alone"** — the callers that pass it (`checkOnURLState`, the follow-up re-extract loop) have just navigated deliberately, so a compare would always answer "yes" and make the gate unconditional; at up to `MaxStates` iterations that is tens of minutes of pure sleeping inside a 30-minute budget. `TestSettleGateIgnoresEmptyPreviousURL` locks this in. The probe returns URL *and* busy in one round-trip because it is on the hottest path.
- **In-page scripts use `__TOKEN__` substitution, never `fmt.Sprintf`.** Several script bodies contain their own `%` signs (URL-encoding character classes, a `%s` format-specifier guard); a format-verb scan corrupts them into `%!s(MISSING)`. `TestInPageScriptsUseTokenSubstitution` enforces this. A script whose token is fixed for the crawl (the speculative one) is rendered once in `New` — it is multi-KB and would otherwise be rebuilt and re-shipped per state.
- **The two priming sources share a dedup set but not a budget.** `selectUnprimedLinks` caps on the SIZE of the shared `primedLinks` map (correct for the anchor primer, whose budget *is* the crawl's total priming allowance); `selectUnprimedLinksBudgeted` caps on how many NEW URLs one call contributes. Any second source must use the budgeted variant — otherwise whichever primer runs first silently consumes the other's allowance. Both delegate to `selectUnprimed`, which takes the cap as a predicate. `harvestSpeculativeLinks` checks its remaining allowance **first**, before the eval: once spent, every later state would otherwise pay a full-document scan to learn there is nothing left.
- **Frontier seeding is a whole-crawl pass, not an index-page step.** `seedFrontier` runs in `crawlWithBrowser` between `initializeIndexState` and `crawlLoop`, alongside `runFollowUpPasses`/`retryFailedActions`/`writeGraphDump`. It navigates to other locations and folds each into the graph, so it cannot sit among the landing-page passes; running it there also guarantees scope adoption is decided and the capture retargeted first. Locations are recorded up to `SeedMaxURLs` (1000) but only `SeedMaxCrawlURLs` (25) are browsed into states, chosen by `selectCrawlableSeeds`, which rounds over path *shapes* (`seedPathShape` collapses identifier-looking segments) so a sitemap dominated by one template cannot spend the whole allowance inside it.
- **`fetchURLsInPage` chunks (`primeChunkSize`).** It is the shared tail of every primer and is bounded by one eval timeout; a list larger than the window can drain does not finish late, it errors and the whole batch reports as failed. A chunk that times out stops the rest — the host is slower than the window and the remaining chunks would fare no better.
- **Follow-up and retry sweeps are gated on `shouldTerminate`.** Both are no-ops when the crawl stopped on its budget, the state cap, or a failure streak — a streak means the application is not answering, which no retry fixes. The retry sweep only collects actions the normal path was about to drop for good (`DisableInputsForAction` returned false), never ones it already re-queued.
- **Self-registration is a write and stays opt-in** (`SelfRegister`, enabled by `--intensity deep`). Single-flighted per host, never submits to an off-host action. It fills through the form handler so the identity lands in the shared `FillContext` and is reused by `buildLoginCreds` whether or not registration logged the browser in.
- **One browser context per host.** The generic `groupByHost` groups targets (shared with the re-spider phase — same ordering contract, different element type) and `openSpiderSession` opens a shared `SpiderSession` for groups of 2+, so cookies, local storage and capture dedup persist across a host's targets. A single-target group, `VIGOLIUM_SPIDER_NO_SESSION_REUSE`, or a launch failure all fall back to a fresh browser per target. A crawl error on a shared session abandons the whole group — the browser may be wedged — and those targets count as processed, not as ceiling-skipped.
- **Both browser phases build their `SpiderConfig` from `buildSpiderConfig`.** The re-spider phase overrides only its budgets and record source. Keeping two builders is how a field added to one phase silently goes missing from the other — which had already happened to `SelfRegister` and the graph output before this was unified.
- **`GraphOutputDir` is a directory, not a path.** The crawl names its own file from the target it actually runs against (`buildCrawlerConfig` → `crawler.GraphOutputPathFor`), because a session reuses one base config across a host's seeds and replaces only `TargetURL`; a precomputed path would be whatever the first target implied. The DOM is deliberately excluded from the dump; the selector and form values on each edge are the point, since they are what make a transition replayable.

### Output Formats

On the scan commands the `--format` flag selects output format: `console` (default), `jsonl`, `html`, `sarif`, `sqlite` (aliases `sqlite3`, `db`), or `fs` (alias `file-system`). Multiple formats can be combined (`--format jsonl,html`). **Alias spellings live in one table** — `formatAliases`/`canonicalFormat` in `pkg/cli/scan.go`, consumed by both `normalizeScanFormats` and `parseExportFormats` — because `fs` is valid on the scan commands *and* on `vigolium export`, so a per-command alias map would have to carry the same alias twice and would leave it working on one command and unknown on the other. Matching is case-insensitive. An alias that canonicalizes to a format a given command does not accept still fails that command's own valid-list check, and the error quotes what the user typed. HTML reports use an embedded ag-grid template (`public/static-reports/`) and require `-o/--output`. HTML format is supported for discovery and spidering phases. The `sqlite` format dumps the run's standalone database to `<output>.sqlite` via `VACUUM INTO` and requires `-S/--stateless` (the per-run temp DB) plus `-o/--output`; under `--split-by-host` each per-host file is named `<base>-<host>.sqlite`. The exported file reopens directly with `vigolium finding/traffic -S --db <file>.sqlite`.

`vigolium export --format` is also a comma-separated list (`html,markdown,bundle`), with formats `html`, `report`, `pdf`, `jsonl`, `markdown` (alias `md`), `sarif`, `bundle` (alias `gz`), `fs`. Four contracts govern it and must not regress. **One format keeps `-o` verbatim** — `--format html -o report` writes exactly `report`, so extension-deriving only kicks in from the second format onward; multi-format then requires `-o` as a *base* (one `-o` cannot name three files) and derives each path through `types.StripFormatExtension` + `types.FormatOutputPath`, the single source of truth shared with the scan commands' `OutputPathForFormat` (it is why `bundle`'s `.tar.gz` and `.tgz` are stripped as **two-part** extensions — `filepath.Ext` sees only `.gz` and would derive `run.tar.html`). **`{ts}`/`{project-uuid}` expand once on the base, before per-format derivation**, because `{ts}` is stamped at expansion time and a per-format expansion would let `pdf` (which shells out to headless Chrome) land on a later second than its siblings and scatter one run across several timestamps. **The database is read once**: `exportRun` (`pkg/cli/export.go`) caches the DB handle, the materialized envelope set, and the auto-detected report meta across every format, which is safe because the renderers treat the item slice as read-only — the HTML/bundle body trimming rewrites each item's marshaled JSON, not the structs. **A failing format does not discard its siblings**: in multi-format mode the error is reported inline and the run continues, exiting non-zero with a `N of M formats failed` summary (a single format still returns its bare error unchanged). Per-format count blocks are suppressed under multi-format in favor of one unified `Exports` list (`printExportSummary`, shared with the scan side). `vigolium db export -f` remains single-valued.

The `sarif` format (`pkg/output/format_sarif.go`) writes a SARIF 2.1.0 log so a run can be ingested by GitHub code scanning, DefectDojo, the VS Code SARIF Viewer and other aggregators. It renders from `buildReportData` like every other document format and shares the `reportGenerator` signature, so it is available on `scan`/`scan-url`/`scan-request`/`run` (via `reportFormats`, which also covers the `-S` stateless and agentic `--format` paths), `vigolium export`, and `vigolium import --format`. The structs are hand-rolled rather than taken from `projectdiscovery/sarif` (still an indirect dep, still unused) because the schema is plain JSON and the mapping is where the decisions are. Five invariants: **the primary location is the source file when there is one and the URL otherwise** — only a file-anchored result can be annotated onto a diff, so audit/piolium findings must not be demoted to their URL, and the URL survives as a `relatedLocation`; **an absolute audit path is only made repo-relative on a `/<repoName>/` segment match** (`sarifSourceURI`), never on a guessed prefix, because a wrong strip silently pins the alert to the wrong file; **evidence rides in `webRequest`/`webResponse`**, the spec's own DAST fields, not in the message text, and repeated headers are joined rather than last-wins so a `Set-Cookie` a finding rests on is never dropped; **`info` maps to `level: "note"`, never `"none"`** — consumers filter `none` out entirely, which would erase every informational observation; and **`results`/`rules` serialize as `[]` on a clean scan**, since an absent array reads as a malformed run rather than as zero findings. `security-severity` is written to the *rule* properties (where GitHub reads it to bucket an alert) as well as the result's, CWE becomes the zero-padded `external/cwe/cwe-079` tag GitHub links to MITRE, and `FindingHash` becomes `partialFingerprints["vigoliumFindingHash/v1"]` so a consumer tracks one finding across re-scans instead of reopening it every run. The encoder disables Go's HTML escaping (payload evidence is full of `&`/`<`/`>`) and bodies are capped at `sarifMaxBodyBytes`, recorded as `properties.evidenceTruncated` rather than silently. `$schema` points at `docs.oasis-open.org`, deliberately not the `raw.githubusercontent.com/oasis-tcs/sarif-spec` URL most tools copied from GitHub's docs — that one is branch-qualified and 404s since the repo renamed `master` to `main`.

The `fs` format (alias `file-system`, `pkg/cli/fsexport.go`) writes a flat, browsable filesystem tree so a coding agent (or anyone with `ls`/`grep`/`jq`) can investigate a scan with no DB. It writes two sibling directories off the `-o` base — defaulting to `vigolium` in the cwd when no `-o` is given, so `-o run` yields `run-traffic/` + `run-findings/`. Each `<host>/` holds per-host zero-padded ids (assigned in `sent_at` order, so re-exports are reproducible): `<id>.req` (a leading `@target <scheme>://<authority>` line then the raw request verbatim — directly replayable by stripping line 1), `<id>.resp.headers` (status line + headers), and `<id>.resp.body` (gzip-decoded so it greps clean). `<host>/<id>.md` under `-findings/` renders each finding cross-linked to its `.req` file (falling back to the finding's inline request/response when the linked record was filtered out). Each sibling dir carries an `index.json` (flat array, jq-friendly) mapping ids → method/url/status/content-type and, for traffic, the top severity of any finding touching that record. Available on `vigolium export`, `vigolium db export` (honoring its filters), and `scan`/`scan-url`/`scan-request`/`run` (works with or without `-S`; `--split-by-host` is a no-op since `fs` already splits by host). Honors `--omit-response` (drops the `.resp.*` files). The shared layout/rendering lives in `pkg/fsexport`.

The same tree can be produced **live** by the ingestion server: `vigolium server --mirror-fs <dir>` (config `server.mirror_fs_path`) mirrors every saved HTTP record and finding to `<dir>/traffic/` + `<dir>/findings/` as they're persisted — in addition to the database — so an external agent can read ingested Burp/proxy traffic as files in real time. It's wired via optional `Repository.OnRecordSaved`/`OnFindingSaved` callbacks (`pkg/database/repository.go`) the server sets only when the flag is on (CLI scans are unaffected), feeding `fsexport.Mirror` — a background-goroutine writer that never blocks the DB save path, uses append-only `index.jsonl` (vs the one-shot export's `index.json` array), and resumes per-host id numbering from the existing tree across restarts.

### Driving Vigolium from a coding agent

Vigolium is built to be shelled out to by an LLM/coding agent. Key contracts (full guide: `docs/coding-agent.md`):

- **Two JSON contracts:** `-j/--json` on read/query commands (`finding`, `traffic`, `db`) emits a single structured object with **compact, token-aware** request/response bodies (header-kept, body-preview-capped with `body_size`/`body_sha256`/`body_truncated`, binary/static bodies stubbed as `body_omitted:"binary"`, findings get a windowed `response_evidence` snippet). The bulk `{"type":...,"data":{...}}` stream stays on `--format jsonl` / `export`. The shared serializer is `pkg/cli/agentview.go`.
- **Output shaping flags** on `finding`/`traffic`/`db ls`: `--compact` (metadata only), `--fields a,b,c` (project JSON keys), `--full-body` (complete bodies), plus `finding --with-records` (embed linked HTTP records → self-contained triage bundle), `--min-severity`, and `--agentic-scan <uuid>` (findings from an agent run; expands to the whole run tree via `resolveAgenticScanTree`).
- **Time filtering** via `--from`/`--to` (aliased `--since`/`--until`) on `finding`/`traffic`/`db ls`/`db export`/`replay`, plus `db clean --before` and swarm `--records-from since=|until=`, all sharing one parser (`pkg/cli/internal/clicommon/timefilter.go`, `ParseSince`/`ParseUntil`, wired through `parseDateRangeFlags` in `pkg/cli/date_filter.go`). Aliases are registered as **data** through `addFlagAliases(cmd, map)` — cobra's `SetGlobalNormalizationFunc` is an overwriting setter, so two independent closures racing for that one slot would leave whichever registered first silently dead; the map accumulates per command, making registration order irrelevant. Error labels come from `flagAliasLabel` over the same table, never hand-written. Accepts relative offsets (`2d`, `12h`, `30m`, `1w`, compound `1h30m`, optional `ago`), `today`/`yesterday`/`now`, `YYYY-MM-DD`, `YYYY-MM-DD HH:MM[:SS]`, and RFC3339. Two contracts that must not regress: bare dates and wall-clock times resolve in the **local** zone (UTC midnight silently dropped the first hours of the local day — `--since today` is the flag's whole point), and a bare date on an **upper** bound snaps to end-of-day so `--from D --to D` is the full day D rather than an empty range. `db clean --before` deliberately uses `ParseSince` (no end-of-day snap) so the named day survives the DELETE. Inverted ranges are a hard error, not silently-empty output.
- **Exit-code gating:** `scan`/`scan-url`/`scan-request`/`run` take `--fail-on <severity>` — exit non-zero when a finding at/above that severity is present (output still written first; `--soft-fail` overrides; per-child under `-P`). Logic in `pkg/cli/scan_fail_on.go` + `severity_gate.go`.
- **Agentic scans** (`agent autopilot|swarm|audit`) under `--json` route the live stream to stderr and print a single summary object to stdout (`{agentic_scan_uuid, status, counts_by_severity, session_dir, top_findings, query}`) via `emitAgentScanJSONSummary` (`pkg/cli/agent_scan_summary.go`), so an agent gets a handle + ready follow-up query without chasing session-dir files.

### Fuzzing primitive (`vigolium fuzz`)

`vigolium fuzz` (`pkg/fuzz/` engine + `pkg/cli/fuzz.go`) is a low-level, agent-driven fuzzing **primitive** — deliberately NOT a scanner. It injects a caller-supplied payload set into chosen positions of ONE request and streams per-payload response signals (status/size/words/lines/time/reflection/baseline-delta) with match/filter gating and auto-calibration against the target's catch-all. It makes no vulnerability decision and emits no findings: the caller (a coding agent) brings the intelligence. For confirmation-backed detection of known classes, route to the hardened module scanner (`scan-request -m ...`) instead — `fuzz` fills only the gap the modules can't express (custom payloads, an exact position, wordlist-scale discovery).

Reuse, not reinvention: the send/diff path is `replay.SendRaw` (the exported low-level send under `replay.Do`); positions come from `pkg/httpmsg` insertion points (or a literal `FUZZ` marker anywhere / method rewrite); payload **classes** (`--class sqli,xss,…`) come from `pkg/payloads` (the shared catalog extracted from the former `jsext.builtinPayloads`, still backing `vigolium.payloads()`); wordlists read from the embedded `internal/resources/wordlists`. Positions: a `FUZZ` marker wins if present (request-line occurrences are auto-encoded so space-bearing payloads stay well-formed); else `--fuzz method|path|params|param-name|headers|cookies|all` (default all insertion points), `--point TYPE:name`, or `--fuzz-header` (which **injects** a header the request doesn't carry rather than erroring — `X-Forwarded-For` is interesting precisely because the client never sends it). Payloads combine `--class` + `-w/--wordlist` (builtin or file) + `-p/--payload` (inline). `--no-calibrate` disables catch-all suppression (suppressed results carry `"calibrated":true`). Output is JSONL (matched-only unless `--all-results`); under `-j/--json` the JSONL streams to stderr and ONE summary object prints to stdout (`{target, sent, matched, calibrated, baseline, top_results, anomalies, query}`) via `emitFuzzJSONSummary`. `--fail-on-match` exits 3 for CI/agent gating. `--dry-run` resolves positions/payloads and prints the exact bytes each would send with **zero** network traffic (the pre-flight an agent needs before committing to a run); `--ignore-scope` overrides the project-scope guard. Source resolution reuses replay's resolvers (positional URL / `-i` curl-raw-burp-base64-url-stdin / `-u` record / stdin). The `replay` CLI no longer exposes `-m/--mutate` — payload/insertion-point fuzzing lives entirely in `fuzz` (`replay` re-sends and confirms, with `--raw-request`/`--raw-request-file` for exact-byte overrides). The `pkg/replay` library (including the exported `ParseMutationFlag` and `Options.Mutations`) and the agent's in-process `replay_request` tool are unchanged and still apply mutations.

**Anomaly detection (`-a/--anomaly`, `pkg/fuzz/anomaly.go`)** is the alternative to hand-written matchers: writing a matcher requires knowing the interesting size/status up front, so instead each response is scored against the baseline **and against the run's own population**. The population reference is what makes it work on an unknown target — a status change every payload triggers is the endpoint's normal behaviour, not a signal, and only rarity distinguishes those. Signals and weights: `error_signature` (45, a leaked SQL/stack/template error the baseline lacked — database errors go through `modkit.MatchSQLError`, the repo's single source of truth, rather than a local copy), `server_error`/`status_now_ok` (40, the latter being 4xx→2xx, i.e. auth-bypass-shaped), `size_outlier`/`unique_body` (30), `rare_status`/`time_outlier`/`header_changed` on Location/WWW-Authenticate (25), `status_changed`/`status_redirect`/`reflected_unencoded` (20). Thresholds low=25/medium=45/high=70 via `--anomaly-threshold`. Outliers use **median-absolute-deviation**, not stddev — a fuzz population is full of outliers by construction and they would inflate a stddev enough to hide themselves. Population signals stay silent below `--anomaly-min-population` (default 12). Scoring is **two-pass** and split by reference: `baselineSignals` (vs the baseline) is computed once in the worker, `populationSignals` (vs the run) from a `snapshot()` taken once per pass — so `rescoreAnomalies` rescores everything against the finished population without retaining a single response body, and the medians are sorted once per run instead of once per send. With `--anomaly` and no explicit matchers, "interesting" replaces "keep everything" as the gate. It reports where to look, never a verdict — the primitive stance holds.

**Matcher grammar:** numeric matcher/exclude flags take `N`, `N-M`, `>N`, `>=N`, `<N`, `<=N`, `!N` (comma-separated, `pkg/fuzz/predicate.go`) — exact equality alone is near-useless for sizes, since a page carrying a timestamp or CSRF token is never byte-identical twice. A bare `--match-time 500` still means `>=500`. `--match-header 'Name: regex'` (or bare `Name` for presence) matches response headers; `--match-mode all` requires every category instead of any. `Matchers`/`Filters` are both aliases of one `Criteria` type so a signal you can match on is always one you can exclude on. Reflection reports `reflected_raw` (verbatim) separately from an escaped echo, and `reflected_in` names the location (`body`, `header:Location`) — header reflection is the whole signal for open redirect and response splitting, and conflating a verbatim echo with an HTML-escaped one hides the difference between "this might execute" and "the app escaped it".

**Attack modes (`--mode`, `pkg/fuzz/attack.go`):** numbered markers `FUZZ`, `FUZZ2`… become separate positions; `-w users.txt:FUZZ -w pass.txt:FUZZ2` binds a list to one. `sniper` (default, one position at a time) | `batteringram` (same payload everywhere) | `pitchfork` (lists in lockstep — credential *pairs*, bounded by the shortest list) | `clusterbomb` (every combination). `Job.Cases` carries the expanded plan. `replaceKeyword` refuses to match a marker followed by a digit, so `FUZZ` can never eat the prefix of `FUZZ2` and substitution order is irrelevant. `MaxCases` bounds clusterbomb expansion so a runaway product is a clear error rather than an OOM. Multi-position modes are **marker-only** and error otherwise: an `httpmsg` insertion point builds from the request it was analyzed against, so applying a second would discard the first's edit. **Baseline timing:** `--baseline-samples` (default 1; 3 under `--anomaly`) sends the un-fuzzed request N times for a mean+stddev, giving each result a `time_z` — the way to express a time-based signal without guessing a per-target millisecond threshold.

**Curl parity.** `fuzz` accepts curl's long-form flags (`--cookie/--user/--user-agent/--referer/--data-raw/--data-binary/--data-urlencode/--form/--form-string/--get/--head/--insecure/--verify-tls/--cacert/--cert/--key/--location/--max-redirs/--connect-timeout/--max-time/--compressed/--http1.1/--http2/--resolve/--path-as-is`) — long forms only, because the short ones are already taken by vigolium meanings (`-u` record UUID, `-i` input, `-w` wordlist, `-c` concurrency). Body assembly is **shared with the curl parser** (exported `curl.ResolveData`/`BuildMultipartBody`/`GuessContentType` in `pkg/input/formats/curl/body.go`; multipart is built with `mime/multipart`, not hand-written framing) so `--data-urlencode` and `--form` behave identically whether they arrive as flags or inside a pasted curl command. `-X`/`-H`/`-d` apply to **every** source, not just a positional URL (`fuzz.Overrides`), and land before position analysis so a marker introduced by `-H 'X-Forwarded-For: FUZZ'` is discovered. `--auth-session`/`--session-id`/`--no-cookies` mirror replay (`resolveAuthSessionHeaders` is shared). Header edits go through `httpmsg.AddOrReplaceHeader` and bodies through `httpmsg.SetBodyString`, **never** `utils.AddOrReplaceHeader` — the latter's `GetHeaderOffsets` never matches a name, so it appends unconditionally and would leave two `Content-Length` headers on a request. `-H` parsing reuses `replay.ParseHeaderFlag` so `fuzz -H` and `replay -H` accept the same syntax, and the cookie jar reuses `openSessionJar`.

### Replay (`vigolium replay`)

There is **one** replay implementation: the `pkg/replay` engine (also behind the agent's in-process `replay_request` tool). `vigolium traffic --replay` is a thin shortcut for `replay` in bulk mode — `runTrafficReplayShim` (`pkg/cli/traffic_replay.go`) calls `buildTrafficFilters` (the same selection the listing path uses) and hands the resulting `database.QueryFilters` to `runReplayBulk`. Do not re-add a second send/compare path to `traffic`, and do not re-introduce a filter-by-filter mapping between the two commands' flag globals: `runReplayBulk` takes filters precisely so a filter added to `traffic` reaches `--replay` with nothing to keep in sync. Only send behaviour (`applyTrafficReplayFlags`) is mapped onto replay's globals.

The shortcut preserves two traffic behaviors that differ from `replay`'s defaults: `--pretty` is forced unless `-j` (traffic defaults to the comparison table, replay to JSON), and `--no-redirects` is forced (traffic --replay never followed redirects, and following them changes the status a comparison reports). Because selection is traffic's own, the `-n/--limit` cap applies — an unfiltered `traffic --replay` re-sends the page it would have listed, not the whole database. Only `replay` can *change* the request — `-H/--header`, `--auth-session`, `-t/--target`, `--session-id`, `--raw-request`, and the Burp send/stage targets have no traffic equivalent.

**Flag-name collision:** `traffic --header` is a record *search filter*; `replay -H/--header` is a header *override*. On `replay` the filter is therefore spelled `--header-search` / `--exclude-header-search`, and the shim maps `traffic --header` onto it. Combining them is the useful case: `replay --header-search 'X-Api-Key' -H 'Cookie: session=other'`. `-H` replaces a whole header value (`utils.AddOrReplaceHeader`), so it is not additive per-cookie; `--auth-session` merges first and `-H` wins.

Record selection for both commands runs through `queryTrafficRecords` (`pkg/cli/traffic_bridge.go`), which takes the bridge URL as a parameter so bulk replay also merges live Burp Proxy history under `-B/--burp-bridge-url`. Because live-bridge records have no DB row, `persistReplayResponse` refuses `--in-replace` on `burpbridge.IsBridgeUUID` UUIDs; it writes through `openReadDB` (the store the records came from, so `-S` updates the export being replayed, not the project DB) and rejects `--glob-db`, whose merge DB is temporary.

### Bridge vendor labelling (`pkg/burpbridge`)

`-B/--burp-bridge-url` (alias `--caido-bridge-url`) points at **one protocol** that both the Burp extension and the Caido plugin serve, so which vendor is listening is *discovered*, not declared. Each reply to `/health`, `/search` and `/inspect` carries an `implementation` identity (`vigolium-burp-bridge` / `vigolium-caido-bridge`), which `sourceForImplementation` maps through the closed `implementationSources` table to the `http_records.source` label (`burp` / `caido`, both in `database.BridgeRecordSources`). Five contracts:

- **The listener reports what it *is*, never what the source column should say.** Anything on loopback can answer this protocol, and a listener free to name its own label could claim `scanner` or `finding` — values that do not merely mislabel a row but change which records scan-on-receive feeds back into a scan. Empty or unrecognised identity ⇒ `burp`, which is what every bridge record was labelled as before detection existed.
- **The identity rides on every reply rather than being probed once from `/health`.** The read path (`Query`/`InspectWithLimit`) never calls `/health`, so a probe would cost an extra round trip per process; more importantly a standalone inspect — the server's single-record handler, `traffic -u burp:<ref>` — has no preceding search to learn the vendor from, which is why `/inspect` echoes it too. `Client.resolvedSource` caches the last *reported* identity (never the fallback, or "nobody said" would be indistinguishable from "the listener said Burp") so a listener that echoes on search but not inspect still labels correctly for the rest of the session.
- **`Eligible` admits every bridge vendor; the vendor check happens after the reply.** Eligibility is decided before the request goes out and therefore cannot know who will answer — narrowing it would make `--source caido` never issue the query that would have proved the listener is Caido. Callers apply `MatchesSourceFilter(filters.Source, live.Source)` afterwards and, on a mismatch, drop the live set **and zero its total**: `MergePage` pages over `localTotal+liveTotal`, so a dropped-but-counted set reports more records than it can show. One bridge is one vendor, so this is all-or-nothing rather than a per-record filter.
- **`UUIDPrefix` stays `burp:` for both vendors.** It is a routing token meaning "this record lives behind the bridge, not in the database", not a provenance label — vendor lives in `Source`. Making it per-vendor would mean `IsBridgeUUID`, `InspectWithLimit`'s `TrimPrefix` (which hard-errors when the trim is a no-op), the replay `--in-replace` guard and the server's inspect handler all growing a prefix set.
- **`ImportIntoRepository` is the path that persists**, so it stamps `inspection.Source()` rather than the constant; a row mislabelled here outlives the session and cannot be reclassified afterwards.

The push direction is labelled too: `X-Vigolium-Source` on `POST /api/ingest-http` (`ingestSource` in `pkg/server/handlers_ingest.go`) lets a client declare `burp`/`caido` instead of the generic `ingest-server` every HTTP client shares — same labels as the bridge path, so one `--source caido` covers traffic that arrived either way. It is an **allowlist, not a passthrough**, for the same reason the implementation table is. Both vendors are in `database.IngestRecordSources`; omitting them is silent, since the rows land in the database and the scan-on-receive poller simply never selects them.

`--with-browser` (`pkg/cli/replay_browser.go`) is **not** a diff mode. `spitolas.ProbeResult` carries no status code and no body, so a navigation cannot produce a `replay.Summary`; those runs emit a `browser` object (`requested_url`, `final_url`, `title`, `dialogs`, `method_note`) with `result` null, rather than a hollow summary whose zero-valued status would read as a real comparison. `validateReplayFlags` rejects it alongside every flag downstream of the send (`--in-replace`, the Burp targets, `--raw-request`).
